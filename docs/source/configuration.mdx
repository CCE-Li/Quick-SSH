# 配置说明

Quick-SSH 把数据分成几类：标准 OpenSSH 格式的主机配置、系统安全凭据库中的密码，以及若干 JSON 程序设置文件。

| 文件 | 内容 |
|------|------|
| `~/.ssh/config` | 主机列表（标准 OpenSSH 格式） |
| 系统凭据库 | 保存的登录密码，**永不写入** SSH 配置 |
| `~/.qsshrc` | 程序行为设置 |
| `agent.json` | AI Agent 配置（服务商 / 模型 / 权限 / 超时） |
| `dashboard.json` | Dashboard 布局与 Profile |
| `ui.json` | TUI 界面状态（如主机列表分隔线比例） |

其中 `agent.json`、`dashboard.json`、`ui.json` 位于平台配置目录：Windows 为 `%APPDATA%\quick-ssh\`，Linux / macOS 为 `~/.config/quick-ssh/`。这些文件都可以通过 [Web 界面](/webui) 编辑。

## SSH 配置 (~/.ssh/config)

Quick-SSH 的主机连接配置保存在 `~/.ssh/config` 文件中，使用标准 OpenSSH 格式。登录密码不写入此文件。

### 格式

```ini
Host mysrv
    HostName 192.168.1.100
    User root
    Port 2222
    IdentityFile ~/.ssh/id_rsa
    ServerAliveInterval 60
    # 自定义注释
```

### 托管字段

Quick-SSH 主动管理的字段（TUI 编辑器和 CLI 命令可读写）：

| 字段 | 说明 |
|------|------|
| `Host` | 主机别名（用于快速连接和标识） |
| `HostName` | 主机地址（IP 或域名） |
| `User` | 登录用户名 |
| `Port` | SSH 端口（默认 22） |
| `IdentityFile` | 身份验证密钥文件路径 |

### 非托管字段

以下字段不会被 qssh 主动解析，但会作为 `Unknown(key, value)` 忠实保留：

- `ServerAliveInterval`
- `ProxyJump`
- `LocalForward`
- `StrictHostKeyChecking`
- 以及其他所有未被托管的 SSH 指令

<Callout title="信息完整性">
  Quick-SSH 采用渐进式解析策略，保证读写过程中不会丢失任何配置信息。全局配置（如 `Host *`）、`Match` 块、`Include` 指令等复杂结构均完整保留在 preamble 中。
</Callout>

### 配置路径

默认路径为 `~/.ssh/config`。如果文件或目录不存在，Quick-SSH 会在首次操作时自动创建。

## 系统安全凭据库

TUI 编辑器中的 **Password** 字段使用操作系统提供的安全存储：

| 平台 | 存储后端 |
|------|---------|
| Windows | Credential Manager |
| macOS | Keychain |
| Linux | Secret Service / keyutils |

凭据以服务名 `quick-ssh` 和主机别名为键保存。编辑主机别名时凭据会迁移，删除主机时会同步清理。密码不会出现在 `~/.ssh/config`、导出 JSON 或日志中。

连接时，Quick-SSH 将自身配置为 OpenSSH 的 AskPass 程序。OpenSSH 仍会优先尝试密钥和 ssh-agent；只有提示登录密码时才会读取对应别名的凭据。私钥口令、主机指纹确认和其他交互提示不会被自动处理。

<Callout title="首次连接">
  首次连接新主机时，请先执行 `ssh <主机别名>` 并手动核对、确认主机指纹。
</Callout>

## 程序设置 (~/.qsshrc)

Quick-SSH 为程序行为设置预留了 `~/.qsshrc` 文件。该文件使用 JSON 格式。

### 配置项

<Properties>
  <Property name="default_port" type="u16" default="22">
    默认 SSH 端口
  </Property>
  <Property name="ping_timeout_secs" type="u64" default="3">
    TCP Ping 超时秒数
  </Property>
  <Property name="upload_concurrency" type="usize" default="3">
    文件上传并发数
  </Property>
  <Property name="ssh_config_path" type="Option<PathBuf>" default="null">
    自定义 SSH 配置路径，为 null 时使用默认路径
  </Property>
</Properties>

### 示例

```json title="~/.qsshrc"
{
  "default_port": 22,
  "ping_timeout_secs": 5,
  "upload_concurrency": 3,
  "ssh_config_path": null
}
```

<Note>
  `~/.qsshrc` 的三个字段可通过 [Web 界面](/webui) 的「程序设置」分组编辑，其中 `ping_timeout_secs` 已用于 TUI 的 Ping 检测。`ssh_config_path` 当前仍为预留字段。
</Note>

## AI Agent 配置 (agent.json)

AI Agent 的配置位于 `agent.json`，完整字段说明和 API Key 解析顺序见 [AI Agent](/ai-agent)。

```json title="~/.config/quick-ssh/agent.json"
{
  "provider": "openai",
  "base_url": "https://api.deepseek.com/v1",
  "model": "deepseek-chat",
  "permission": "ask_before_execute",
  "timeout_secs": 60,
  "api_key": ""
}
```

## Dashboard 配置 (dashboard.json)

Dashboard 工作台的 Profile 与布局位于 `dashboard.json`。`enabled` 列出启用的监控组件，`layout` 是由组件与分屏节点组成的布局树；加载时会按 `enabled` 重建，历史残留的旧布局会被覆盖。

<Callout title="不要手改 layout">
  Dashboard 布局会在加载时按 `enabled` 用内置默认布局重建，直接手改 `dashboard.json` 里的 `layout` 通常会被覆盖。请通过工作台内的 `c` 面板或 Web 界面调整启用的组件。
</Callout>

界面相关的 UI 状态（如主机列表分隔线比例 `main_split_weight`）保存在同目录下的 `ui.json`，与手写的 `~/.qsshrc` 分开。

## 配置工作原理

### 配置模块架构

配置系统采用类型/解析/渲染分离的设计：

```
SSH 配置文件 (文本)
       ↓
parser.rs → 文本解析 → types.rs (SshConfig / HostBlock / SshDirective)
       ↓
writer.rs → 数据结构 → 文本渲染 → 写回文件
```

### 渐进式解析

解析器只识别 `Host` / `HostName` / `User` / `Port` / `IdentityFile` 五个字段：

- 已知字段 → 解析为对应的 `SshDirective` 枚举变体
- 未知字段 → 解析为 `SshDirective::Unknown(key, value)` 保留原始内容
- 全局配置（非 Host 块内容）→ 保留在 `preamble` 字段中
- 每个 Host 块的原始文本 → 保留在 `raw_text` 字段中，用于忠实重建

### 渲染策略

渲染器优先使用 `raw_text` 重建 Host 块（保证注释和空白格式不变），仅在 `raw_text` 为空时使用结构化指令渲染。
